# Threat model

Protect against an unrelated LAN client injecting input, replaying frames, changing the advertised endpoint, stealing plaintext saved credentials, or leaving mouse buttons held after network failure. Assume the user can visually transfer a QR or manual invitation from their own computer and can compare a code before approval. Assume both devices' OS accounts and app binaries are trusted. Malware with access to the user's authenticated OS session, compromised endpoints, shoulder-surfed invitations, LAN denial of service and malicious trusted phones are outside the protection boundary.

Production connections always use TLS 1.2/1.3 and exact certificate pin verification. No trust-all mode or hostname bypass on a public CA connection is used. A custom Android trust manager checks the transferred certificate digest and its validity, rather than accepting any certificate. That design intentionally triggers Android lint's custom-trust-manager review warning. Pairing invites expire after two minutes and rotate after success. QR secrets and tokens are never logged by the product. Device names are rendered as text, not interpreted markup.

Desktop vault data (certificate, private key, trusted token hashes) is AES-256-GCM encrypted with a fresh 96-bit nonce for each write. The 256-bit wrapping key is stored using Windows Credential Manager or macOS Keychain. The encrypted file is `%LOCALAPPDATA%/ThumbPad/vault.bin` or the macOS local application data directory under ThumbPad. Persistence errors fail closed. The certificate is not silently replaced if the vault cannot decrypt. Revocation persists removal and closes active control. Uninstallation preserves the encrypted vault/key so upgrades/reinstalls retain identity. Explicitly revoke trusted phones before decommissioning a computer.

Android encrypts saved computer addresses, fingerprints and bearer tokens with AES-GCM under an Android Keystore key. The installation ID and non-secret UI settings remain in private preferences. Backup is disabled; hardware-backed key protection depends on the device. Tokens are never sent before the pinned TLS handshake completes. The app asks only for internet/local connectivity, haptics and camera (QR scanning); it does not request clipboard, file access, location, contacts, microphone, background persistence or accessibility on Android.

No telemetry, external HTTP resources, remote scripts or cloud endpoints are used. Tauri applies a self-only CSP and restricted native commands. Login startup is opt-in. No UPnP or router changes are performed. Binding is a single private IPv4 address, never `0.0.0.0`. The local network still needs private firewall permission. Do not forward the control port through your router. On an untrusted LAN, a peer can attempt resource exhaustion; the admission caps and handshake deadlines limit retained work, but are not a full denial-of-service defense.

The 6-character displayed code is a visual comparison aid, not the authentication secret; the full 256-bit invite is needed. The desktop still requires approval even if an invitation is captured. Trusted credentials are bearer credentials, not hardware attestation. No claim of a formal security audit is made. Mandatory follow-up before broad release: independent review of pinning, vault recovery, native event safety, CI dependency provenance, Android 17 local-network permission changes and real macOS onboarding.
