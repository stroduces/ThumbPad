# Architecture and decisions

The phone activity renders native Compose Material 3. A ViewModel owns UI/settings, selected computer, touch interpretation and a coroutine-based TLS client. Native MotionEvent samples are converted from physical coordinates to dp; deterministic velocity gain uses displacement/time rather than frame count. The first sample anchors the gesture (no entry jump). A short tap is bounded by cumulative travel and duration, with tests at 60/90/120Hz-equivalent sample counts. Two-finger taps are secondary clicks; right-click, scroll and drag never require them. The side strip is 54dp wide and moves to the left for left-handed use. Palm rejection is a conservative touch-size heuristic; it cannot infer every palm on every device.

Phone outbound work runs on Dispatchers.IO. A replaceable motion slot bounds stale deltas; reliable buttons/scroll/shortcuts retain FIFO ordering. At most 64 queued actions exist, with disconnect on overflow. The writer assigns sequence numbers when draining, flushes pending motion before buttons, expires motion after 50ms in its own monotonic time, and enables TCP_NODELAY. No render loop generates synthetic touch events. Heartbeat round trip uses one Android clock. App stop releases and closes, network callbacks clear drag and reconnect known credentials on network availability, and reconnect clears all pending work with exponential backoff. Full process restart loads encrypted trusted devices; the user chooses which computer to control.

Desktop is Tauri 2 with a bundled local HTML/CSS interface and no browser tab or remote assets. Its Rust core owns TLS, identity, pairing, mDNS, session bounds, watchdog, protocol validation and input dispatch. UI commands are narrow native IPC operations; arbitrary system commands are not exposed. Autostart uses the native Tauri plugin and is user opt-in. The window closes to the native tray/menu bar; quitting disables control, gives the watchdog time to release, and exits. macOS's window remains a normal companion window when opened, with a menu bar tray icon.

One private IPv4 interface is selected at launch. The TLS listener is never wildcard/public by default. mDNS advertises `_thumbpad._tcp.local.` with protocol version 1; manual invitations work when multicast is blocked. mDNS does not transfer credentials or authorize control. IPv6-only LANs, automatic host-interface rebinding, and advanced adapter selection are not yet supported. Relaunch desktop after a network adapter/address change and re-pair if the saved address changed. Known certificate identity is retained.

TLS uses a locally generated P-256 certificate and private key. Android pins the certificate's exact SHA-256 DER digest, checks validity, and requires TLS proof of possession. This is private-identity pin validation rather than public-Web PKI. Pairing requires both an expiring 256-bit invitation and an explicit desktop approval. Only one controller is admitted. Subsequent authentication uses a random 256-bit bearer token inside pinned TLS; the host stores only its hash. Trust can be revoked in the desktop window. Revocation increments a session generation, terminating current control within a watchdog tick.

Platform injection is entirely native: Windows SendInput relative motion/buttons/wheel and allowlisted virtual keys; macOS Quartz CGEvent pointer/buttons/pixel scroll and keyboard events. The OS retains final authority for accessibility and protected desktops. No elevation, browser automation, remote desktop stream, or shell injection exists. Multiple displays use OS global cursor coordinates and native relative motion. Actual behavior across varied monitors/DPI and macOS acceleration requires physical hardware validation.

The host's event parser is fixed-size, strict and versioned. Invalid/nonfinite/range-exceeding payloads, reserved bytes and repeated sequences terminate the session. Session-local RAII releases all buttons on disconnect/error. A three-second input watchdog and 50ms disable/revocation check remain active even during a partial read. TLS admission is capped at eight sessions, pairing at four requests. Before authentication only bounded hello frames are processed.

Shared behavior is specified in `protocol/SPEC.md` and a golden binary vector, asserted in both Rust and Kotlin. Native CI builds the same source on each platform. The loopback harness has explicit volatile identity and a dry input dispatcher; it never changes production trust or mouse state.

Current UI scope includes presets, sensitivity/acceleration/scroll direction, tap/haptics, handedness, awake control, palm rejection, optional extra controls, paired-device switcher, demo, battery at opening and heartbeat RTT. Arbitrary layout editing, arbitrary shortcut mapping, free-text typing, push-to-talk and landscape are deferred; they must not be presented as implemented features. The first release is a working development candidate, pending physical treadmill/device/macOS acceptance.
